# Лабораторна робота №2
## Обґрунтування вибору типів даних

Проєкт: Щоденник тренувань (TrainingDiary).

## Властивості класу Workout

| Властивість | Тип C# | Обґрунтування |
|---|---|---|
| Id | int | Унікальний числовий ідентифікатор тренування. |
| SportType | string | Назва виду спорту зберігається як текст. |
| ExerciseName | string | Назва вправи є текстовим значенням. |
| DurationMinutes | int | Тривалість тренування у цілих хвилинах. |
| Distance | decimal? | Дистанція з десятковою точністю, може бути відсутня. |
| PerformedOn | DateTime | Дата проведення тренування. |

## Перелічуваний тип WorkoutType

Для класифікації тренувань створено enum WorkoutType:

- Strength — силові тренування.
- Cardio — кардіотренування.
- Recovery — відновлення.
- Other — інші тренування.

## Особливості реалізації

- string.Empty — початкове значення текстових властивостей.
- decimal? — nullable-тип для необов'язкової дистанції.
- DateTime.Today — поточна дата за замовчуванням.
- int — використовується для цілих чисел.

## Висновок

Типи даних обрано відповідно до предметної області.
Модель Workout дозволяє описувати спортивні заняття,
їх тривалість, дистанцію та дату виконання.

## Лабораторна робота №4
### Пояснення згенерованого коду Blazor CRUD

1. @page — директива, яка задає URL-адресу сторінки. Наприклад, @page "/workouts" дозволяє відкрити список тренувань.

2. @inject — директива впровадження залежностей. У нашому проєкті IDbContextFactory<TrainingDiaryContext> використовується для створення контексту бази даних SQLite.

3. IQueryable<Workout> — тип запиту до бази даних, який дозволяє застосовувати фільтрацію, сортування та пагінацію до отримання записів.

4. EditForm — компонент Blazor для створення форм введення та редагування. Він забезпечує роботу з моделлю та обробку надсилання форми.

5. @bind-Value — механізм двостороннього зв'язування даних між полями форми і властивостями об'єкта Workout. Зміни у формі передаються відповідним властивостям моделі.

### Результат роботи

Автоматично створено п'ять сторінок CRUD:
Index, Create, Edit, Details, Delete.

Перевірено створення, перегляд, редагування та видалення тренувань.

Реалізовано пагінацію по 5 записів на сторінку.
Перевірено відображення 20 тренувань на 4 сторінках.


## Лабораторна робота №5
### Компоненти Blazor: розмітка, блок коду, параметри

Проєкт: Щоденник тренувань (TrainingDiary).

### Створений компонент
Створено власний компонент Components/WorkoutCard.razor.

Компонент призначений для відображення інформації про тренування та повторного використання на різних сторінках.

### Параметри компонента

1. Workout — об'єкт класу Workout, який містить дані тренування. Позначений атрибутами [Parameter, EditorRequired].

2. Caption — текстовий параметр для зміни заголовка картки.

3. ShowDetails — логічний параметр, який керує відображенням додаткової інформації.

### Використання компонента

Details.razor:
Caption = "Детальна інформація"
ShowDetails = true

Delete.razor:
Caption = "Запис для видалення"
ShowDetails = false

### Результат роботи

Один компонент WorkoutCard використано на двох сторінках.

На сторінці Details відображається повна інформація про тренування.

На сторінці Delete показано скорочену картку без додаткових полів.

Повторення однакової розмітки усунено. Компонент можна використовувати повторно.

Проєкт успішно компілюється командою dotnet build.
